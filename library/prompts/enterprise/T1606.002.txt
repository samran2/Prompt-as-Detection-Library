T1606.002 — SAML Tokens | Enterprise | ATT&CK 19.2 reference
Source: https://attack.mitre.org/techniques/T1606/002
Source tactics: Credential Access
Technique platforms: SaaS, Windows, IaaS, Office Suite, Identity Provider
Parent technique: T1606 — Forge Web Credentials

Task: Propose detection logic, required telemetry, false positives, and bounded test cases.
Output target: Platform-neutral. This is an output instruction, not a verified integration.

Behavior to investigate: An adversary may forge SAML tokens with any permissions claims and lifetimes if they possess a valid SAML token-signing certificate.(Citation: Microsoft SolarWinds Steps) The default lifetime of a SAML token is one hour, but the validity period can be specified in the <code>NotOnOrAfter</code> value of the <code>conditions ...</code> element in a token. This value can be changed using the <code>AccessTokenLifetime</code> in a <code>LifetimeTokenPolicy</code>.(Citation: Microsoft SAML Token Lifetimes) Forged SAML tokens enable adversaries to authenticate across services that use SAML 2.0 as an SSO (single sign-on) mechanism.(Citation: Cyberark Golden SAML)

An adversary may utilize [Private Keys](https://attack.mitre.org/techniques/T1552/004) to compromise an organization's token-signing certificate to create forged SAML tokens. If the adversary has sufficient permissions to establish a new federation trust with their own Active Directory Federation Services (AD FS) server, they may instead generate their own trusted token-signing certificate.(Citation: Microsoft SolarWinds Customer Guidance) This differs from [Steal Application Access Token](https://attack.mitre.org/techniques/T1528) and other similar behaviors in that the tokens are new and forged by the adversary, rather than stolen or intercepted from legitimate users.

An adversary may gain administrative Entra ID privileges if a SAML token is forged which claims to represent a highly privileged account. This may lead to [Use Alternate Authentication Material](https://attack.mitre.org/techniques/T1550), which may bypass multi-factor and other authentication protection mechanisms.(Citation: Microsoft SolarWinds Customer Guidance)
Suggested telemetry (confirm availability): azure:signinlogs; channel: SAML-based login with anomalous issuer or NotOnOrAfter lifetime; data component: Logon Session Metadata; WinEventLog:Security; channel: EventCode=4769, 1200, 1202; data component: User Account Authentication; AWS:CloudTrail; channel: AssumeRoleWithSAML; data component: Web Credential Usage; CloudTrail:Signin; channel: SAML login without corresponding IdP authentication log; data component: Logon Session Creation; WinEventLog:Security; channel: EventCode=4624, 4648; data component: Logon Session Creation; WinEventLog:ADFS; channel: Token issuance events showing anomalous claims or issuers; data component: Web Credential Creation; saas:access; channel: SAML token accepted without preceding login challenge; data component: Web Credential Usage; m365:unified; channel: Abnormal user claims or unexpected elevated role assignment in SAML assertion; data component: Logon Session Metadata; m365:exchange; channel: Mailbox access using SAML token without corresponding MFA event; data component: Web Credential Usage; m365:sharepoint; channel: File access with forged or anomalous SAML claims; data component: Logon Session Creation.
Benign activity to consider: Local-baseline guidance (not a source finding): establish approved activity, expected accounts, assets, schedules and change windows for this behavior. Review source tuning variables; require local evidence before making exclusions.
