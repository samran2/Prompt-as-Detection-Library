Behavior to investigate: An adversary may forge SAML tokens with any permissions claims and lifetimes if they possess a valid SAML token-signing certificate.(Citation: Microsoft SolarWinds Steps) The default lifetime of a SAML token is one hour, but the validity period can be specified in the <code>NotOnOrAfter</code> value of the <code>conditions ...</code> element in a token. This value can be changed using the <code>AccessTokenLifetime</code> in a <code>LifetimeTokenPolicy</code>.(Citation: Microsoft SAML Token Lifetimes) Forged SAML tokens enable adversaries to authenticate across services that use SAML 2.0 as an SSO (single sign-on) mechanism.(Citation: Cyberark Golden SAML)

An adversary may utilize [Private Keys](https://attack.mitre.org/techniques/T1552/004) to compromise an organization's token-signing certificate to create forged SAML tokens. If the adversary has sufficient permissions to establish a new federation trust with their own Active Directory Federation Services (AD FS) server, they may instead generate their own trusted token-signing certificate.(Citation: Microsoft SolarWinds Customer Guidance) This differs from [Steal Application Access Token](https://attack.mitre.org/techniques/T1528) and other similar behaviors in that the tokens are new and forged by the adversary, rather than stolen or intercepted from legitimate users.

An adversary may gain administrative Entra ID privileges if a SAML token is forged which claims to represent a highly privileged account. This may lead to [Use Alternate Authentication Material](https://attack.mitre.org/techniques/T1550), which may bypass multi-factor and other authentication protection mechanisms.(Citation: Microsoft SolarWinds Customer Guidance)

DET0148 — Detection Strategy for Forged SAML Tokens
Strategy source: https://attack.mitre.org/detectionstrategies/DET0148
AN0418 — Analytic 0418
Forged SAML tokens can be observed as authentication attempts with valid signatures but missing expected preceding Kerberos or authentication events. Defenders may correlate SAML assertions with absent Event IDs 4769, 1200, or 1202, or tokens issued with abnormal lifetimes, issuers, or claims compared to baseline.
Analytic platforms: Identity Provider
Source-listed telemetry: azure:signinlogs; channel: SAML-based login with anomalous issuer or NotOnOrAfter lifetime; data component: Logon Session Metadata
Source-listed telemetry: WinEventLog:Security; channel: EventCode=4769, 1200, 1202; data component: User Account Authentication
Source tuning variables (local values must be established): [{"field":"TokenLifetimeThreshold","description":"Defines the maximum expected lifetime of a SAML token (e.g., >1 hour considered anomalous)."},{"field":"TrustedIssuerList","description":"List of approved SAML issuers and certificate thumbprints."}]
AN0419 — Analytic 0419
Forged SAML tokens in IaaS environments often manifest as cross-cloud or cross-account authentication without matching STS events. Defenders may see AssumeRole or GetFederationToken API usage without a corresponding SAML assertion log from the trusted IdP.
Analytic platforms: IaaS
Source-listed telemetry: AWS:CloudTrail; channel: AssumeRoleWithSAML; data component: Web Credential Usage
Source-listed telemetry: CloudTrail:Signin; channel: SAML login without corresponding IdP authentication log; data component: Logon Session Creation
Source tuning variables (local values must be established): [{"field":"CrossAccountUsage","description":"Flag SAML tokens used across unexpected accounts or cloud tenants."}]
AN0420 — Analytic 0420
Forged SAML tokens may be used on Windows systems to authenticate to federated apps without normal Kerberos activity. Defenders may detect anomalous event correlation, where access to SaaS/O365 via SAML occurs without prior TGT requests or user logons.
Analytic platforms: Windows
Source-listed telemetry: WinEventLog:Security; channel: EventCode=4624, 4648; data component: Logon Session Creation
Source-listed telemetry: WinEventLog:ADFS; channel: Token issuance events showing anomalous claims or issuers; data component: Web Credential Creation
Source tuning variables (local values must be established): [{"field":"ClaimAnomalyThreshold","description":"Number of unusual claims in a SAML token (e.g., excessive privileges)."}]
AN0421 — Analytic 0421
Forged SAML tokens can appear as SaaS logins where authentication succeeded without MFA, or where tokens contain claims inconsistent with the user profile. Look for concurrent sessions across different geographies with the same SAML assertion ID.
Analytic platforms: SaaS
Source-listed telemetry: saas:access; channel: SAML token accepted without preceding login challenge; data component: Web Credential Usage
Source-listed telemetry: m365:unified; channel: Abnormal user claims or unexpected elevated role assignment in SAML assertion; data component: Logon Session Metadata
Source tuning variables (local values must be established): [{"field":"GeoVelocityThreshold","description":"Triggers when same SAML token used in different geographies within short timeframe."}]
AN0422 — Analytic 0422
Forged SAML tokens may be leveraged to access O365 apps such as Outlook or SharePoint. Defenders should monitor for token replay across multiple clients or access attempts to privileged mailboxes without prior interactive login.
Analytic platforms: Office Suite
Source-listed telemetry: m365:exchange; channel: Mailbox access using SAML token without corresponding MFA event; data component: Web Credential Usage
Source-listed telemetry: m365:sharepoint; channel: File access with forged or anomalous SAML claims; data component: Logon Session Creation
Source tuning variables (local values must be established): [{"field":"ReplayDetectionThreshold","description":"Number of times a token is reused within short timeframe."}]
