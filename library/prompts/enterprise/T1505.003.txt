Output target: Platform-neutral. This is an output instruction, not a verified integration.

Behavior to investigate: Adversaries may backdoor web servers with web shells to establish persistent access to systems. A Web shell is a Web script that is placed on an openly accessible Web server to allow an adversary to access the Web server as a gateway into a network. A Web shell may provide a set of functions to execute or a command-line interface on the system that hosts the Web server.(Citation: volexity_0day_sophos_FW)

In addition to a server-side script, a Web shell may have a client interface program that is used to talk to the Web server (e.g. [China Chopper](https://attack.mitre.org/software/S0020) Web shell client).(Citation: Lee 2013)
Suggested telemetry (confirm availability): WinEventLog:Sysmon; channel: EventCode=11; data component: File Creation; WinEventLog:Sysmon; channel: EventCode=1; data component: Process Creation; WinEventLog:Security; channel: EventCode=4624, 4648; data component: Logon Session Creation; NSM:Flow; channel: Inbound HTTP POST with suspicious payload size or user-agent; data component: Network Traffic Content; auditd:SYSCALL; channel: new file created in /var/www/html, /srv/http, or similar web root; data component: File Creation; auditd:SYSCALL; channel: apache2 or nginx spawning sh, bash, or python interpreter; data component: Process Creation; NSM:Flow; channel: POST requests to .php, .jsp, .aspx files with high entropy body; data component: Network Traffic Content; macos:unifiedlog; channel: httpd spawning bash, zsh, python, or osascript; data component: Process Creation; auditd:SYSCALL; channel: file write operations in /Library/WebServer/Documents; data component: File Modification.
