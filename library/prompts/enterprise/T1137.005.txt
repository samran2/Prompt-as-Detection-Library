T1137.005 — Outlook Rules | Enterprise | ATT&CK 19.2 reference

Technique platforms: Windows, Office Suite

Output target: Platform-neutral. This is an output instruction, not a verified integration.
Prompt profile: PAD-v0.4.0-dev3 (clear-task-focused-v3)

Behavior to investigate: Adversaries may abuse Microsoft Outlook rules to obtain persistence on a compromised system. Outlook rules allow a user to define automated behavior to manage email messages. A benign rule might, for example, automatically move an email to a particular folder in Outlook if it contains specific words from a specific sender. Malicious Outlook rules can be created that can trigger code execution when an adversary sends a specifically crafted email to that user.(Citation: SilentBreak Outlook Rules)

Once malicious rules have been added to the user’s mailbox, they will be loaded when Outlook is started. Malicious rules will execute when an adversary sends a specifically crafted email to the user.(Citation: SilentBreak Outlook Rules)
Suggested telemetry (confirm availability): WinEventLog:Sysmon; channel: EventCode=1; data component: Process Creation; WinEventLog:Sysmon; channel: EventCode=7; data component: Module Load; WinEventLog:Application; channel: Outlook rule execution failure or abnormal rule execution context; data component: Application Log Content; WinEventLog:PowerShell; channel: PowerShell launched from outlook.exe or triggered without user invocation; data component: Command Execution; m365:unified; channel: Creation or modification of inbox rule outside of normal user behavior; data component: Application Log Content; m365:messagetrace; channel: Inbound email matches crafted rule trigger pattern tied to persistence logic; data component: Command Execution.

AN0263 — Analytic 0263
Adversary uses a tool like Ruler or MFCMapi to create a malicious Outlook rule that triggers execution upon receipt of a crafted email. On email delivery, Outlook executes the rule, resulting in code execution (e.g., launching mshta.exe or PowerShell). Outlook spawns a non-standard child process, often unsanctioned, without user interaction.
