T1555.002 — Securityd Memory | Enterprise | ATT&CK 19.2 reference
Source: https://attack.mitre.org/techniques/T1555/002
Source tactics: Credential Access
Technique platforms: Linux, macOS

Task: Propose detection logic, required telemetry, false positives, and bounded test cases.
Output target: Platform-neutral. This is an output instruction, not a verified integration.

Behavior to investigate: An adversary with root access may gather credentials by reading `securityd`’s memory. `securityd` is a service/daemon responsible for implementing security protocols such as encryption and authorization.(Citation: Apple Dev SecurityD) A privileged adversary may be able to scan through `securityd`'s memory to find the correct sequence of keys to decrypt the user’s logon keychain. This may provide the adversary with various plaintext passwords, such as those for users, WiFi, mail, browsers, certificates, secure notes, etc.(Citation: OS X Keychain)(Citation: OSX Keydnap malware)

In OS X prior to El Capitan, users with root access can read plaintext keychain passwords of logged-in users because Apple’s keychain implementation allows these credentials to be cached so that users are not repeatedly prompted for passwords.(Citation: OS X Keychain)(Citation: External to DA, the OS X Way) Apple’s `securityd` utility takes the user’s logon password, encrypts it with PBKDF2, and stores this master key in memory. Apple also uses a set of keys and algorithms to encrypt the user’s password, but once the master key is found, an adversary need only iterate over the other values to unlock the final password.(Citation: OS X Keychain)
Suggested telemetry (confirm availability): macos:unifiedlog; channel: ptrace or task_for_pid; data component: Process Access; macos:unifiedlog; channel: execution of memory inspection tools (lldb, gdb, osqueryi); data component: Process Creation; auditd:SYSCALL; channel: ptrace attach; data component: Process Access; auditd:FILE; channel: /proc/*/mem read attempt; data component: File Access; auditd:EXECVE; channel: gcore, gdb, strings, hexdump execution; data component: Command Execution.
